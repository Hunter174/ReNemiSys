# Frozen blind physics gate, protocol `v3-blind-v1` (ReNemiSys #4)

**This file, the opponent implementation and the eight seeds must be committed before #5 trains a v3 policy. Do not run the sealed evaluator, inspect outcomes or use its seeds in training/development.** Existing 15137/29011/310xx/410xx/420xx/510xx evaluations are already visible and cannot serve as fresh v3 proof. Development-only seed 700 exists for an infrastructure dry run with existing v2 weights; it is not a held-out score. This is a local Godot 4.4.1 CPU prototype, not game/production certification.

## Predeclared experimental contract

- Blind seeds: **61001, 61013, 61027, 61039, 61051, 61069, 61081, 61097**. Jitter ten starting slots per seed and freeze one initial player/goblin state. No script may collect or train on these numbers, and `ARENA_DIAGNOSTIC` may only use 700–707. Team modes: shared v3, separately loaded v2 baseline, fixed pressure, conservative guard/retreat, observation-only FSM. Separate Godot process for **each** policy, seed and duel/group mode. Compare v3 and v2 on the *same* sealed seed set only after v3 artifact is frozen; treat subsequent reuse as non-independent.
- Four five-second phases of **one continuous twenty-second bout** with persistent HP, stamina, position and tactical beliefs: `wall_switch`, `bait_hold`, `reach_cycle`, `cross_feint`. Record intermediate HP/defeats and the ONE final win/loss/timeout, never count four phase snapshots as independent fights. Group starts with ten 4-HP goblins and a 100-HP player; duel starts with one 4-HP goblin and a 3-HP player. No negative HP or hits after death. Report reversals and attrition, including zero-hit/timeouts as valid outcomes.
- `wall_switch`: if player within 90 pixels of x-wall or y-wall (x < 90 or > 870, y < 90 or > 510), move toward nearest live goblin; otherwise tangent to it for the first 2.5 seconds, then reverse tangent. `bait_hold`: retreat from a guarding goblin, otherwise move toward it for the first 0.25 seconds of each 1.4-second cycle and opposite tangent the rest. `reach_cycle`: chase when distance >150 pixels, strafe tangentially when <65, kite otherwise. `cross_feint`: strafe tangent while player HP above 70% of initial; afterward reverse tangent unless nearest goblin HP <=2, then chase. Player speed stays 92 px/s, collisions/damage/masks remain Godot-owned. The opponent uses visible NPC action/HP/position only, never policy weights, scripted future choices or fabricated hits.
- Cross-process checks assert the SAME initial slot hashes and versioned **opponent rule contract** per phase, legal actions, model/artifact variant, completed 20 seconds, non-increasing HP/cumulative deaths and honest final outcomes. The responsive opponent's actual trajectories can and should differ by team. Save raw per-bout report **outside Git**. Do not interpret `--fixed-fps` wall time as rendered decision/frame timing.

## Pre-open advancement and reporting gates

The #3 development-only budgets gate whether a frozen v3 artifact may enter evaluation: >=4/8 wins, <=3/8 deaths versus the separate development post-attack-lunge style; >=90% v2 group damage and no extra group attrition on those same development starts. #7 handles 8–20 rendered-agent CPU timing and fallback separately. Once v3 is frozen, run the sealed evaluator **once** for v2 and once for v3, report all 8 seeds, group HP/damage/deaths, duel win/loss/timeouts, phase reversal and any failures. Precommitted comparative acceptance for this experiment: v3 duel wins >= v2, v3 duel defeats <= v2, group damage >=90% v2, group goblins defeated <= v2 (no sacrifice of survival for damage), zero illegal actions; if any fails, #6 reports FAIL and #2 remains open. Eight seeded bouts per team/mode provide limited evidence, not a significance/production claim. A new model iteration requires a *newly frozen* opponent/seed set; no tuning against these scores.
